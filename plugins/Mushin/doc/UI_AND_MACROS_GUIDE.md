# Mushin UI, Controls, Pages & Macro Reflection Guide

This document explains how every control type, panel, page, and macro interaction in **Mushin** was built for Akai MPC standalone hardware, and why each choice was made, as a reference for future updates and plugins.

---

## 1. Pages & Function-Key Tab Architecture

The MPC touch screen has **6 hardware function keys** (`F1`–`F6`) along the bottom. Mushin defines 7 logical pages in [`ui.json`](../ui.json) and maps them onto the 6 function keys in [`bin/make_skin.py`](../bin/make_skin.py):

| Logical Page | `fnKeyIndex` | `fnKeySubIndex` | Purpose |
|---|---:|---:|---|
| `MAIN` | 0 | 0 | 8 Performance Macro Orbs (2 Q-Link banks) |
| `S-CURVE` | 1 | 0 | S-Curve Waveshaper + Info Decay |
| `FILTER` | 2 | 0 | Filter A, Filter B, Routing (`SERIAL` / `PARAL`) |
| `LFO` | 3 | 0 | LFO 1 & 2 + Noise Oscillator |
| `LFO MTX` | 3 | 1 | LFO 1 & 2 Modulation Matrix (sub-tab of `LFO`) |
| `GATE` | 4 | 0 | Trance Gate + Pattern Strip + AHDS Envelope |
| `DLY+LIM` | 5 | 0 | Stereo Delay + Final Limiter |

### Q-Link Alignment & Compaction
- `ui.json` sets `"qlinkGroups": "rows"` so every 4-column row of controls corresponds to one hardware Q-Link bank (`Q-Link 13..16`, `9..12`, `5..8`, `1..4`).
- Leaving an entire visual row `"empty"` (for example, Row 2 on `MAIN` and `LFO` where taller custom graphics or visual breathing room sit) causes `tools/gen_ui.py` to emit an all-`-1` Q-Link bank, creating a dead bank when cycling Q-Links.
- `bin/make_skin.py` compacts `Screen Mode Q-Links` on `MAIN` (Tab 1) and `LFO` (Tab 4) into consecutive top-down banks (`13..16` → `9..12` → `5..8`) and remaps `Tab`/`SubTab` indices to match `fn_key_map` (`LFO MTX` → `Tab 4, SubTab 2`).

## 2. Panels & Background Graphics

Each page uses a `1280×628` background PNG generated by [`bin/make_panels.py`](../bin/make_panels.py):
- **Top & bottom half-screen zones**: Rounded-corner rectangles (`#10141A` fill, `#2E3A48` border) with a cyan (`#00E5FF`) 5×7 bitmap title embedded in the top border (`S-CURVE`, `INFO DECAY`, `FILTER A`, `FILTER B`, `LFO 1 & 2`, `NOISE OSC`, etc.).
- **Concise panel-scoped parameter names**: Because the panel border already names the section, [`src/Mushin.cpp`](../src/Mushin.cpp) exposes short `Name` strings (`Cutoff`, `Reso`, `Drive`, `Grit`, `Active`, `Mix`) while keeping unique parameter `id` strings (`filter_a_cutoff`, `filter_b_cutoff`, etc.). `bin/make_skin.py` maps parameter indices via `UI_PARAM_KEYS` into `build/params_ui.json` so `tools/gen_ui.py` binds every control unambiguously.
- **Static `Text` label rule**: On MPC hardware, `"type": "Text"` labels with `"handleName": "Data"` are hidden as unbound handles. `bin/make_skin.py` sets `"handleName": "Invalid"` and `"showWhenDataModelInvalid": "Show"` on all static `Text` labels.

## 3. Controls by Widget Type (How & Why)

### 3.1 Rotary Knobs (`knob`)
- **Unipolar (`"widget": "knob"`)**: Used for continuous frequency, drive, grit, resonance, depth, and threshold parameters (`Drive`, `Cutoff`, `Reso`, `LFO 1 Freq`, etc.). Uses `knob_uni.png` filmstrip.
- **Bipolar (`"widget": "knob", "polarity": "bipolar"`)**: Used on `LFO MTX` (`-1.00 .. +1.00`) so center-zero modulation amounts show bidirectional travel via `knob_bi.png`.

### 3.2 Horizontal Faders (`fader`)
- `"widget": "fader"` (`fader_h_uni.png`, `248×36` horizontal drag) is used for level/mix/envelope-time controls (`Gain`, `Dry/Wet Mix`, `Decay Mix`, `Noise Level`, `Gate Mix`, `Gate Start/Hold/End`, `Delay Mix`, `Limit Mix`) to visually separate mix/envelope sliders from tone/frequency knobs.

### 3.3 Boolean Switches (`switch` on `boolParam`)
- Parameters declared with `mpc::boolParam` (`Exhaustion`, `Auto Gain`, `Decay Active`, `Exh Link`, `Noise Active`, `Gate Active`, `Delay Active`, `Delay Sync`, `Limit Active`) become `toggle` pill switches (`toggle_on.png` / `toggle_off.png`).

### 3.4 2–4 Way Segmented Switches with Baked Icons (`switch` on `choiceParam`)
- On MPC hardware, `gen_ui.py`'s default `Text` label overlays on `seg2`/`seg3`/`seg4` buttons rendered as blank boxes.
- **Solution**: [`bin/make_button_icons.ps1`](../bin/make_button_icons.ps1) composites anti-aliased vector shapes/icons directly onto `seg2_{on,off}.png` (`122×40`), `seg3_{on,off}.png` (`80×40`), and `seg4_{on,off}.png` (`58×40`):
  - `A Type` / `B Type` (`radioFType`, 4): Clean sine, Vintage tanh S-curve, Acid 303 spike, Digital staircase.
  - `A Mode` / `B Mode` (`radioFMode`, 4): LP, HP, BP, Notch curves.
  - `Routing` (`radioRoute`, 2): Serial `[A]--[B]` vs Parallel split/join diagram.
  - `Noise Route` (`radioNRoute`, 3): Signal flow dot before `[D]`, between `[D]`/`[F]`, or post-`[F]`.
  - `Gate Rate` (`radioGRate`, 3): Step bars + `1/16`, `1/8`, `1/4`.
  - `Delay Tempo` (`radioDTempo`, 4): `1/16`, `1/8`, `1/4`, `1/2` + dot count.
  - `Limit Mode` (`radioLMode`, 2): Brickwall `CLN` vs soft-knee `LMC`.
- `bin/make_skin.py` clones `radio2`/`radio3`/`radio4` into per-control `localComponentDefinitions`, binds the `btn_*` PNGs, and strips the redundant `seg *` `Text` labels.

### 3.5 5–6 Way Segmented Icon Switches (`LFO 1 Wave`, `LFO 2 Wave`, `Noise Type`)
- `tools/gen_ui.py` only defines `SEGMENTS` for 2, 3, and 4 choices.
- To give **LFO 1 Wave** (5 choices: Sine, Triangle, Saw, Square, Random), **LFO 2 Wave** (5 choices), and **Noise Type** (6 choices: White, Pink, Sine, Triangle, Saw, Square) direct pressable icon buttons matching the original Windows VST:
  - `ui.json` keeps them as `"widget": "knob", "overlay": "menu"` so `gen_ui.py` allocates their grid slots and Q-Link entries cleanly.
  - `make_button_icons.ps1` (`New-SegCanvas`) slices the left and right rounded borders of `seg4_{on,off}.png` into `46×40` (`btn_lfowave_0..4`) and `38×40` (`btn_noisetype_0..5`) canvases and draws the waveform icons (including dense jagged spikes for White noise and an accent-cyan 1/f wave for Pink noise).
  - `make_skin.py` (`make_multi_icon_radio_def`) builds `radioLfoWave` (`5` buttons at `x = 16, 66, 116, 166, 216`, `w = 46`) and `radioNoiseType` (`6` buttons at `x = 17, 58, 99, 140, 181, 222`, `w = 38`), and swaps the tab component `"type"` from `"knob"` to `"radioLfoWave"` / `"radioNoiseType"`.

### 3.6 Menu Overlay Knobs (`knob` + `overlay: "menu"`)
- Used for long choice lists where segmented buttons would be too cramped, such as `Gate Pattern` (8 patterns). Turning the knob or tapping/opening the overlay selects the pattern, while the adjacent `gatePatStrip` displays the 16-step pattern graphic.

### 3.7 Custom `FilmStrip` Visuals (`MAIN` Orbs & `GATE` Pattern Strip)
- `TUI.json` has no `"type": "Image"` widget. Dynamic graphics use `"type": "Knob"` with `"knobType": "FilmStrip"` inside `localComponentDefinitions` (`acceptsHWFocus: "No"`, `ignoreMousePresses: true`):
  - `orbStrip0..7` (`orb_strip_0..7.png`, 16 frames) on `MAIN`, bound to the 8 macro parameters.
  - `gatePatStrip` (`gate_pat_strip.png`, 8 frames) on `GATE`, bound to `Gate Pattern`.

### 3.8 AHDS Envelope Widget (`GATE`)
- `make_gate_envelope` in `bin/make_skin.py` places an `"type": "Envelope"` (`envelopeType: "AHDS"`) in Row 4 (`23 498 1238 107`) bound to `Gate Start` (`attackHandle`), `Gate Hold` (`holdHandle`), and `Gate End` (`decayHandle`), with unused handles (`sustainHandle`, `attackShapeHandle`, `decayShapeHandle`) set to `"Invalid"` and `forceHideShapeHandles: true`.

## 4. Performance Macros & Reflecting Parameters on Detail Pages

### 4.1 The Problem with Hidden DSP-Only Offsets
Originally, the 8 macros (`kMacroExhaustion .. kMacroSmash`, parameters `77..84`) only added offsets inside `process()`. Turning a macro changed the sound, but the knobs and switches on `S-CURVE`, `FILTER`, `LFO`, `LFO MTX`, `GATE`, and `DLY+LIM` stayed at their old values, making it unnatural to switch to a detail page and fine-tune the sound.

### 4.2 Base-Value Tracking & Host Reflection (`Mushin.cpp`)
Mushin now uses **bidirectional base-value tracking** so macros directly drive the underlying parameters and keep every page in sync:

1. **`baseValues_[kNumParams]`**: Stores the pre-macro ("base") plain value of every parameter.
2. **Macro moved (`parameterChanged` for `kMacroExhaustion .. kMacroSmash`)**:
   - `applyMacros()` computes the effective target value for every macro-controlled parameter from `baseValues_` + current macro positions.
   - `setTargetParam(idx, val)` clamps to `[param.min, param.max]`, writes `set(idx, clamped)` only when changed (`> 1e-5`), and calls `notifyHostParameterChanged(idx)` (`audioMasterAutomate`) so the MPC updates the controls on all other pages.
   - An `updatingFromMacro_` re-entrancy guard prevents any synchronous host `setParameter` echo from being treated as a user edit.
3. **Detail control edited (`parameterChanged` for `0 .. 76`)**:
   - `updateBaseFromTarget(idx, plainValue)` inverse-maps the user's edited value back into `baseValues_[idx]` (for example, `baseDrive = clamp(val - 12.0 * mExh, 1, 20)` and `baseFACutoff = clamp(val * 2^(7*mChoke + 3.5*mKinetic), 20, 20000)`).
   - `process()` reads `get(...)` directly without duplicate macro offsets, so any detail edit takes effect immediately and is preserved when macros are dialed back down.
4. **Parallel-Aware `CHOKE` Macro**:
   - In `SERIAL` mode (`baseValues_[kRouting] == 0`), `CHOKE` engages `chokeBand`: Filter A (LP) sweeps down `-7.0 * mChoke` octaves while Filter B switches to `HP` (`mode = 1`) and sweeps up from `20 Hz`, forming a serial bandpass choke.
   - In `PARAL` mode (`baseValues_[kRouting] == 1`), switching Filter B to `HP` would let highs pass through the parallel branch instead of choking. Therefore, when `isParallel` is true, `chokeBand` is disabled, Filter B stays in its base mode (`LP`), and both Filter A and Filter B sweep downward `-7.0 * mChoke` octaves together.
   - Toggling `Routing` while `CHOKE > 0.02` immediately re-runs `applyMacros()`.
5. **State & Preset Round-Trip Safety**:
   - `framework/mpc_plugin.h` provides `isBulkLoading()` (true during `internalLoadState()` and `setProgram()`). During bulk loads, `parameterChanged()` updates `baseValues_[index]` without running `applyMacros()` or emitting `audioMasterAutomate`.
   - `saveExtraState()` / `loadExtraState()` persist `baseValues_` in an `"MSHB"` chunk block so saved projects restore both the visible parameters and the exact pre-macro base values.

## 5. Build & Skin Regeneration Workflow

Because `tools/build.py` copies `plugins/Mushin/skins/` verbatim when that directory exists, always run the skin pipeline after changing `ui.json`, `bin/make_skin.py`, `bin/make_button_icons.ps1`, or parameter definitions in `src/Mushin.cpp`:

```powershell
# 1. (Optional) Regenerate panel background PNGs if panel titles/layout changed
python plugins/Mushin/bin/make_panels.py

# 2. Regenerate TUI.json, Q-Links.json, and all 66 button icon PNGs
python plugins/Mushin/bin/make_skin.py

# 3. Compile native + arm32 + arm64 and validate assets/TUI.json
python tools/build.py plugins/Mushin

# 4. Run host_sim verification
.sdk-tools/host_sim plugins/Mushin/build/native/mushin.dll test
```
